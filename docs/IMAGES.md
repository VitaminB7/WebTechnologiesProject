# รูปภาพเมื่อใช้งานโปรเจกต์ในเครื่องอื่น

## รูปที่มากับโปรเจกต์

- รูปห้องพักต้นฉบับ 80 รูปอยู่ใน `prototype_rooms/L-xxxx/` และอยู่ใน Git
- รูปสมาชิกทีมอยู่ใน `sec2_gr1_fe_src/public/img/team/` และอยู่ใน Git
- หน้า Team ต้องใช้ `public/js/team.js` เวอร์ชันที่อ้างอิงรูปจริงด้วย ไม่ใช่เฉพาะไฟล์รูป

เมื่อ clone หรือ pull แล้ว ให้ติดตั้ง dependencies ตั้งค่าฐานข้อมูล และเปิดทั้ง
Web Service และ Front-end ตาม README รูปทีมให้บริการโดย Front-end
ส่วนรูปห้องพักให้บริการโดย Web Service

Web Service จะลงทะเบียนรูปห้องในฐานข้อมูลเมื่อเริ่มต้น หาก URL เป็น
`/uploads/prototype-L-0203-1.jpg` แต่ไม่พบไฟล์ใน `uploads` ระบบจะใช้ไฟล์
`prototype_rooms/L-0203/L-0203-1.jpg` ที่มากับ Git แทน โดยยังใช้ URL เดิม
จึงไม่ต้องส่งโฟลเดอร์ uploads จากเครื่องผู้พัฒนาให้เพื่อน และไม่ต้อง reset
ฐานข้อมูลเพื่อแก้ปัญหารูปต้นฉบับหาย

## รูปที่อัปโหลดเพิ่มผ่านหน้า Admin

รูปใหม่ยังบันทึกใน `sec2_gr1_ws_src/uploads/` หรือ `UPLOAD_DIR` ที่ตั้งค่าไว้
และมีข้อมูลอ้างอิงในตาราง `RoomImage` โฟลเดอร์นี้ไม่ถูกเก็บใน Git
ดังนั้น git pull ไม่ได้ซิงก์รูปที่อัปโหลดใหม่หรือข้อมูลฐานข้อมูลระหว่างเครื่อง

หากต้องการให้ทุกคนเห็นรูปที่อัปโหลดใหม่ชุดเดียวกัน ให้ใช้ Web Service
ฐานข้อมูล และพื้นที่เก็บ uploads ชุดเดียวกันบนเซิร์ฟเวอร์ หรือส่งทั้งไฟล์รูป
และข้อมูล RoomImage ที่ตรงกันให้เครื่องปลายทาง ห้ามกำหนด API_ORIGIN เป็น
localhost ของเครื่องผู้พัฒนาเมื่อให้เครื่องอื่นเรียกใช้งานผ่านเครือข่าย

## ตรวจสอบรูปต้นฉบับโดยไม่ต้องเปิด MySQL

```bash
cd sec2_gr1_ws_src
node --test tests/bundled-images.test.js
```

การทดสอบใช้โฟลเดอร์ uploads ชั่วคราวและฐานข้อมูลจำลอง จึงไม่แก้ไขรูป
หรือฐานข้อมูลที่ใช้งานจริง
